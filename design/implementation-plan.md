# 承認された方針と段階

第1段階の実装、およびそのGitHub Pages公開を2026-10-30に承認済み。第2段階以降、サービス導入、Ollama設定変更、以後の公開は別途承認が必要。

1. 既存データのバックアップ、診断、隔離復元の検証。
2. 問題・デッキの版、イベント、評価、前提知識、提案・承認・外部記憶の契約を確定。
3. Ollama・Gemmaの早期検証。最終契約でJSON生成、日本語の改善指示、抽象化、性能を評価。
4. 版管理・個別履歴・認証・端末間同期。単純な難易度選択の実装対象をここから第5段階に置く。
5. Good/Bad、理由、全体フィードバック、低評価一覧。難易度選択は遅くともここで実装。
6. ローカル資料、正式な生成・改善、元問題を残す補助問題、承認・適用履歴。
7. 承認済みの科目別・全科目共通方針の検索・参照・改訂・効果追跡。
8. 理解度に応じた頻度・難易度の自動調整。

## 通信時の方針（今回の実装対象外）

- 端末内の回答保存に失敗した場合は、次へ進ませず失敗を通知する。
- 端末内保存に成功した場合は、クラウド同期未完了でも次へ進める。
- 同期失敗時は回答を保持し、同じ回答IDで後から再送する。
- 未同期件数・経過時間に応じて警告し、恒久的な認証・権限エラーを区別する。
- 件数しきい値は第4段階で検証して決める。端末容量に保存できない場合は進行を止める。
- 完全なオフライン演習は低優先。確実な端末内保存と送信待ち管理は回答保護のために必要。

## 難易度と正確性

基礎easy・標準normal・応用hardの単独／複数選択はAI分析を必要とせず、第4〜5段階で実装する。理解度に基づく自動調整は第8段階に残す。

AIの処理速度より内容の正確性を優先する。数百問は小さなバッチで管理し、根拠・検証・人による確認・採用状態を問題ごとに保持する。AIの点検だけで誤りゼロと判定しない。

## 公開

既存のGitHub Pages、docs配置方式を維持する。第1段階は利用者の公開承認に基づき、ビルド済み成果物をdocsへコピーし、コミット・プッシュして公開する。今後の公開も必ず利用者確認を取る。
