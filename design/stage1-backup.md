# 第1段階: バックアップと隔離復元

実装範囲はバックアップ、診断、隔離復元の検証のみ。本番への復元・保存形式の移行・同期・AI機能は含まない。

## 作業範囲と公開

第1段階の実装後、2026-10-30に利用者から既存の`docs/`方式での公開承認を受けた。Ollamaと外部サービスの設定は変更しない。公開やローカルのテストが成功しても、PC Chrome・iPhone Safariの実データの保全完了とは扱わない。

## 使い方

開発用の独立した入口:

```powershell
flutter run -d chrome --web-port 8081 -t lib/backup_main.dart
```

この入口は`AppState`を生成せず、`load()`による既存の進捗移行も実行しない。localhostの保存領域は公開URLとは異なる。ここに公開アプリの実データが見えなくても、空のバックアップを実データのバックアップとして扱わない。

通常画面には「バックアップ・復元検証」ボタンも追加した。ただし、通常起動では従来の`AppState.load()`が先に走る。原文を移行処理より先に取得する場合は、次の専用起動経路を使用する。

公開版の反映後は、既存URLに`?backup=1`を付けて直接起動する:

```text
https://harubaru-cell.github.io/quiz-app/?backup=1
```

PCとiPhoneの両方で使うには、この更新の反映を確認する。旧版が表示される場合も、保存データを消すための「サイトデータ削除」は行わず、通常の再読み込み等で更新を確認する。画面に「バックアップ・復元検証」が表示されたことを確認する。

1. 学習を途中終了して保存を待ち、他のタブでの学習を止める。
2. 同じ公開URL・ブラウザ・プロファイルで専用入口を開く。
3. 端末名を「PC Chrome」「iPhone Safari」などに設定する。
4. 「現在のデータからバックアップを作成」を押し、件数と診断を確認する。
5. 「ファイルを保存」を押す。PCではリポジトリ・docsの外、iPhoneでは「ファイル」等へ保存する。
6. 「保存したバックアップファイルを選択」で、そのファイルを選び直す。
7. SHA-256と作成データの一致表示を確認し、「別DBへの復元・再読込を検証」を押す。
8. 原文・音声の一致、処理前後の現行データの一致、診断の注意事項を確認する。

ファイル保存開始はブラウザへの依頼にすぎず、ファイル保存完了や実データ保全の証明ではない。保存ファイルの再選択が必要。取得元が異なるファイルも検証できるが、その取得元の実データを確認したことにはならない。

iPhone Safariのダウンロード・ファイル選択は実機確認が未実施。ホーム画面に追加したアプリを使っている場合は、その保存領域もSafariタブと同一と決めつけず、実際の件数を確認する。

## 保持する内容

SharedPreferences Webの実装に合わせ、次のlocalStorage値をJSONの外側の文字列ラッパーも含め原文のまま保存する。

- `flutter.quiz_app.decks`: デッキ、問題、正解候補、解説、難易度、タグ、日時等。
- `flutter.quiz_app.histories`: 既存のセッション履歴と回答。
- `flutter.quiz_app.deck_stats`: デッキごとの集計。
- `flutter.quiz_app.question_progress`: 問題別進捗。
- `flutter.quiz_app.study_cycles`: 一周の順序、区切り、位置、回答列、デッキ署名。
- 同じ`flutter.quiz_app.`接頭辞の未知のキーも原文で保持し、未解釈として表示する。
- 未作成キーは`null`として明示し、空文字・空配列とは区別する。
- `quiz_study_audio_database`の`audio_files`内の全レコードをBase64で保持する。孤立音声も省略しない。DBの存在・版も保持する。

関係のないlocalStorageキーや認証情報は取得しない。既存モデルで診断するが、`toJson()`の再生成値で置き換えない。通常のデッキ取り込みはバックアップ復元には利用しない。

外部URLの音声ファイルそのものは取得しない。そのような参照や不足音声がある場合は、完全性を確認できないエラーとし、復元検証を有効にしない。将来の未知の音声ストアも黙って省略しない。

## ファイルと診断

- 形式: `quiz-study-backup`、バックアップ形式版1。
- メタデータ: 作成日時UTC、取得元Origin、端末名、対象アプリ・保存形式、取得方法。
- 原文と音声を含むペイロード全体のSHA-256。
- 上限64 MiB。上限超過時に切り捨て保存はしない。
- SHA-256は欠損・変更検出用。暗号化や作成者の認証ではない。
- ファイル名は`*.quiz-backup.json`。Gitで既定名や重複ダウンロード名を除外するが、利用者が任意に改名したファイルまで自動保護するものではない。必ずリポジトリ外へ保存する。

取得は原文と音声を2回読み、内容が一致しなければ中止する。localStorageとIndexedDBをまたぐ原子的なスナップショットではないため、他タブや別ウィンドウでの同時更新を止める必要がある。

診断は領域ごとの件数、JSON・モデル形式、履歴内の集計、進捗内の集計、一周の順序と位置、参照の欠損、音声の不足等を確認する。履歴・問題別進捗・一周の回答は重なるため合算しない。全ての学習内容が意味的に正しいことや、過去に失われた履歴を復元できることを保証する診断ではない。

壊れた保存値も原文の退避は可能。ただし整合性エラーのあるバックアップは正常な復元検証に進めない。削除済み問題への過去の参照や、旧進捗未作成は注意として保持し、自動修復・移行しない。

## 隔離の実装

読取元インターフェースに書込・削除APIはない。SharedPreferencesの初期化・setter・既存の音声保存サービスも呼ばない。

復元先はコードで生成した`quiz_study_backup_sandbox_<UUID v4>`。バックアップから宛先DB名を指定できない。保存値と音声を専用DBへ書き込み、接続を閉じてから再オープンして読み出す。原文・音声・未作成キーを含むダイジェスト、現行データの処理前後のダイジェストを比較する。正常終了時には検証DBを削除する。削除対象は専用の名前形式に制限し、本来の音声DBや任意の名前は拒否する。

存在しない元音声DBを読むときは作成トランザクションを中止し、空DBを新設しない。読取不能を「音声なし」として成功扱いしない。Chromeのブラウザテストで実際のDB一覧・原文・音声の不変性を確認する。

## 検証と限界

実ブラウザの保存処理は、Flutterの描画エンジンに依存しない検証入口でも確認できる。

```powershell
dart tool/run_backup_browser_probe.dart
```

インストール済みChromeを新しい使い捨てプロファイルで起動し、127.0.0.1の一時サーバー上で合成データだけを処理する。元のブラウザプロファイルは使用しない。終了時にサーバー・Chromeを停止する。テスト用プロファイルや生成物はGit対象外の`build/backup-browser-probe/`に残る。ブラウザの場所は`CHROME_EXECUTABLE`で指定可能。

Flutter標準のChromeテスト入口も`test/browser/backup_browser_test.dart`に用意しているが、この環境ではSDK付属スナップショットの古いパス参照、ソース入口では描画側の読み込み停止により完走していない。SDKを変更せず、上記の独立したブラウザ検証で保存処理を確認する。標準Chromeテストの成功や、実機でのファイル保存完了とは扱わない。

検証の途中でブラウザを強制終了した場合には、専用接頭辞の検証DBが残る可能性がある。本番データには書き戻さない。正常終了時に削除するのは、その実行で作成した専用DBだけである。

自動試験は架空データのみを使う。3形式、未知の追加項目、改行、日本語・中国語、日時、欠損、改変、集計不整合、一周途中、音声、保存失敗、取得中の変化を扱う。

実際の学習データの内容・件数は未取得。PC Chrome・iPhone Safariの個別バックアップも未確認。実データを使う前に公開方法と実機確認の承認が必要。本番への完全復元機能は今回提供しないが、現行保存値を再現するための原文・未作成情報・音声・形式情報を保持する。

第2段階以降に進む前に、両端末の件数、バックアップファイルの再読込、隔離検証、注意・エラーの有無を確認する。
